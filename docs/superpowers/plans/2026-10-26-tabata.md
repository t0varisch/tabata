# Табата Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Интервальный таймер-PWA без рекламы с тренировками из блоков и синхронизацией через свой сервер с историей в git.

**Architecture:** Клиент — статическое PWA на GitHub Pages, данные в IndexedDB, работает офлайн. Сервер — один FastAPI-файл в Docker на сервере Романа за Caddy CRM по пути `/tabata/`, хранит `workouts.json` и картинки в git-репозитории, коммит на каждое изменение. Слияние — «последнее изменение побеждает» на уровне тренировки.

**Tech Stack:** Vite 8 + TypeScript 7 без фреймворка, vite-plugin-pwa 2, idb 8, vitest 5 (jsdom), Playwright; Python 3.12 + FastAPI + uvicorn, pytest, git, Docker, Caddy 2.

**Spec:** `docs/superpowers/specs/2026-10-26-tabata-design.md`

## Global Constraints

- Название — «Табата». Интерфейс по-русски. Слово РЕХАБ/REHAB в интерфейсе, текстах и именах файлов не используется (технический адрес `api.rehab-wellness.app` — исключение, разрешено Романом 26.10).
- Без рекламы, трекеров, внешних шрифтов и запросов, кроме сервера синхронизации.
- Время в данных — целые секунды. Значения по умолчанию: подготовка 5 с, финальный отдых выключен, вибрация выключена, быстрый таймер 30/30 × 8.
- Цвета фаз: работа красный, отдых зелёный, подготовка синий. Тёмная тема.
- Без названия блок показывается как «Работа N», где N — номер блока с 1.
- Картинки: не-GIF → до 720 px по большей стороне, WebP 0.8 (запасной JPEG 0.85); GIF как есть, предел 3 МБ.
- Сервер: тело `/sync` до 1 МБ, картинка до 3 МБ, CORS `https://t0varisch.github.io` и `http://localhost:5173`, ключ `Authorization: Bearer`.
- Вёрстка без прокрутки вбок на 390 и 320 px.

## Review Focus

- Фаза нулевой длины (отдых 0, подготовка 0) — пропускается, сигналы не звучат дважды. Тест в Task 1.
- Тренировка без блоков или с 0 сетов — не стартует, кнопка «Старт» неактивна. Тест в Task 1 (`buildPhases` → `[]`) и Task 6.
- Экран выключился или браузер заснул на 95 с — по возвращении таймер стоит на верной фазе по реальному времени. Тест в Task 2.
- Правка тренировки во время идущей синхронизации — правка не теряется, тренировка остаётся «не отправлено». Тест в Task 4.
- Неверный ключ — 401, понятный статус «неверный ключ», локальные данные целы. Тесты в Task 3 и Task 4.

### Task 2: Бегунок таймера

**Files:** Create `src/core/runner.ts`; Test `src/core/runner.test.ts`

**Interfaces:**
- Consumes: `Phase`, `buildPhases` (Task 1).
- Produces:
```ts
export type RunnerState = { index: number; remaining: number; elapsedTotal: number; paused: boolean; done: boolean };
export type RunnerEvents = { onPhase?: (index: number, phase: Phase, phaseStartedAt: number) => void; onDone?: () => void; onPause?: () => void; onResume?: (index: number, remaining: number) => void };
export class Runner {
  constructor(phases: Phase[], events: RunnerEvents, now?: () => number); // now в мс, по умолчанию performance.now
  start(): void; tick(): RunnerState; pause(): void; resume(): void;
  next(): void; prev(): void; stop(): void; state(): RunnerState;
}
```
Время считается от `phaseStartedAt` (мс) и длительности; `tick()` при опоздании проходит сразу несколько фаз, вызывая `onPhase` для каждой. `remaining` — секунды до конца фазы, округление вверх. `prev()` в первой половине секунды фазы уходит на предыдущую, иначе в начало текущей.

### Task 3: Сервер синхронизации

**Files:** Create `server/app.py`, `server/requirements.txt` (fastapi, uvicorn[standard]), `server/Dockerfile` (python:3.12-slim + git, uvicorn на 8080), `server/docker-compose.yml` (сервис `tabata-sync`, `container_name: tabata-sync`, `env_file: .env`, том `../tabata-data:/data`, внешняя сеть `rehabcrm_default`, `restart: unless-stopped`), `server/.env.example`; Test `server/test_app.py`

**Interfaces — Produces (HTTP, все кроме /health под ключом):**
- `GET /health` → `{"ok": true}`
- `POST /sync` body `{"workouts": Workout[], "device": str}` → `{"workouts": Workout[], "missingImages": [sha]}` — все тренировки сервера после слияния, включая `deleted`; `missingImages` — sha из `image` всех блоков, файлов которых нет.
- `PUT /images/{sha}` raw body → 204; 400 если sha256(body) ≠ sha; 413 если > 3 МБ.
- `GET /images/{sha}` → файл с Content-Type по расширению; 404.
- `create_app(data_dir: Path, key: str) -> FastAPI` — для тестов; модуль создаёт `app = create_app(Path(os.environ["DATA_DIR"]), os.environ["TABATA_KEY"])`.

Слияние: для каждой входящей тренировки берётся та, у которой `updatedAt` больше; при равенстве остаётся серверная. Если что-то изменилось — `workouts.json` (ключи по id, `sort_keys`, `indent=2`, `ensure_ascii=False`) пишется атомарно и коммитится: `sync <device>: +новые ~изменённые -удалённые`. Картинки — `images/<sha>.<ext>` (ext по Content-Type: webp/jpg/png/gif), коммит `image <sha[:8]>`. Репозиторий данных создаётся при первом запуске (`git init`, `user.name tabata-sync`). Запись — под `threading.Lock`.
