# Табата — интервальный таймер с синхронизацией через свой сервер

Дата: 2026-10-26. Заказчик и единственный пользователь — Роман.
Статусы: **[Роман 26.10]** — сказал Роман; **[решение Claude]** — моя проба, Роман может отменить.

## Зачем

Бесплатные Tabata-таймеры на Android с рекламой, а перенастроить время (не 30/30, а другое) — долго. Нужен свой таймер без рекламы: открыл, ткнул тренировку, пошло. Успех — от открытия приложения до старта меньше 5 секунд [Роман 26.10].

Пример тренировки Романа: выбросы гантелей 4 × (30 с работы / 30 с отдыха), затем канат 3 × (60/60), затем комплекс с гирями. Упражнение меняет во время отдыха, пауз между блоками нет [Роман 26.10].

## Цели

- Быстрый таймер на главном экране: работа, отдых, циклы, подготовка; помнит последние значения; одной кнопкой сохраняется как тренировка [Роман 26.10].
- Неограниченное число сохранённых тренировок. Тренировка = подготовка + блоки подряд. Блок = число сетов, работа (с), отдых (с), по желанию название и картинка. Без названия — «Работа 1», «Работа 2» по номеру блока [Роман 26.10].
- Подготовка перед стартом настраивается у каждой тренировки, по умолчанию 5 с [Роман 26.10].
- Финальный отдых после последней работы — переключатель у тренировки, по умолчанию выключен [Роман 26.10].
- Звук: короткие писки «3-2-1» перед сменой фазы, длинный на смену. Звучат поверх музыки и не останавливают её [Роман 26.10].
- Вибрация на смену фазы — настройка, по умолчанию выключена [Роман 26.10].
- Экран не гаснет во время тренировки. Крупные цифры, читаемые с 2 м [Роман 26.10].
- Цвета фаз: красный — работа, зелёный — отдых [Роман 26.10, сказал «или синий» для отдыха — проба]; подготовка — синий [решение Claude].
- Тёмная тема [Роман 26.10].
- Работает без сети. Синхронизация телефон ↔ компьютер через сервер Романа, когда сеть есть [Роман 26.10].
- На сервере — файл с тренировками и история всех изменений [Роман 26.10].
- Картинки из галереи, гифки анимированные; картинки уменьшаются и тоже синхронизируются [Роман 26.10].
- Название — «Табата» [Роман 26.10].

## Не цели [Роман 26.10]

Журнал сделанных тренировок, статистика, голосовые подсказки, паузы между блоками, несколько пользователей, готовый набор картинок.

## Анти-цели

- Реклама, трекеры, внешние запросы кроме своего сервера.
- Таймер «уплывает»: фазы считаются от реального времени, а не накоплением тиков.
- Потеря тренировки при одновременной правке на двух устройствах разных тренировок.

## Устройство

### Клиент [решение Claude, по образцу «Точки»]
- Vite + TypeScript без фреймворка, PWA (`vite-plugin-pwa`), IndexedDB через `idb`. Код — `C:\Projects\tabata`, репозиторий `t0varisch/tabata` (публичный, как «Точка»), выкладка на GitHub Pages по push в `main`: https://t0varisch.github.io/tabata/
- Ставится на Android через Chrome «Добавить на главный экран», на компьютер — установкой PWA из Chrome или ярлыком `--app`, как «Печатка».
- Приложению нужны скрипты, поэтому раздаётся ссылкой, не файлом (глобальное правило про HTML).

### Экраны
1. **Главная.** Сверху быстрый таймер: работа, отдых, циклы, подготовка — степперы ±, нажатие на число открывает ввод. Кнопки «Старт» и «Сохранить как тренировку». Ниже список тренировок: нажатие — старт, значок карандаша — редактор. «+ Тренировка». Шестерёнка — настройки. Точка статуса синхронизации.
2. **Редактор.** Название, подготовка, финальный отдых (переключатель), блоки: название (необязательно), картинка (необязательно), сеты, работа, отдых; блоки добавлять, удалять, двигать вверх/вниз. Удалить тренировку. Сохраняется сразу при изменении.
3. **Тренировка.** Фон цветом фазы на весь экран. Огромные цифры оставшегося времени фазы. Название фазы: «Работа» + название упражнения или «Работа N»; «Отдых»; «Приготовься». Во время отдыха строка «Дальше: <упражнение>» [решение Claude — помогает сменить снаряд]. Картинка блока. «Сет 2 из 4», «Блок 1 из 3». Сколько осталось на всю тренировку. Кнопки: назад на интервал, пауза/продолжить, вперёд на интервал, стоп. В конце — «Готово» и длинный сигнал.
4. **Настройки.** Ключ синхронизации, вибрация, «Синхронизировать сейчас», время последней синхронизации и ошибка, если есть.

### Таймер
- Тренировка разворачивается в плоский список фаз: подготовка → для каждого блока для каждого сета: работа, отдых. Последний отдых тренировки выкидывается, если финальный отдых выключен. Подготовка 0 — без подготовки.
- Время фазы считается от момента её начала по `performance.now()`; экран обновляется ~10 раз в секунду.
- Сигналы ставятся в расписание Web Audio в момент начала фазы (за 3, 2, 1 с — короткий; в конце — длинный), поэтому не опаздывают, если браузер притормозил скрипты. Пауза и перемотка отменяют поставленные сигналы и ставят заново.
- `navigator.audioSession.type = "ambient"`, где поддерживается, чтобы не глушить музыку. На Android Chrome Web Audio не забирает аудиофокус — проверить на телефоне Романа.
- Wake Lock на время тренировки, повторный запрос при возврате на вкладку.

### Данные
```ts
type Block = { id: string; name: string; image: string | null; sets: number; work: number; rest: number };
type Workout = { id: string; name: string; prep: number; finalRest: boolean; blocks: Block[]; updatedAt: number; deleted?: boolean };
```
`image` — SHA-256 содержимого картинки. Время — секунды, целые. Удаление — пометка `deleted: true` с новым `updatedAt` (чтобы удаление доехало до второго устройства).

Картинки [решение Claude]: обычные — уменьшаются до 720 px по большей стороне, WebP 0.8 (запасной вариант JPEG); GIF — как есть до 3 МБ, больше — сообщение «гифка больше 3 МБ».

### Синхронизация [решение Claude]
- Правило «побеждает последнее изменение» действует **на уровне тренировки** по `updatedAt`: правки разных тренировок на двух устройствах обе сохраняются.
- Клиент помечает изменённые тренировки «не отправлено». Синхронизация: при запуске, при появлении сети, при возврате в приложение, через 2 с после правки, кнопкой.
- `POST /sync {workouts: [изменённые]}` → сервер сливает, возвращает все тренировки и список картинок, которых у него нет; клиент догружает их `PUT /images/<sha>`, недостающие у себя скачивает `GET /images/<sha>`.

### Сервер [решение Claude]
- Python 3.12 + FastAPI, один файл, Docker-контейнер `tabata-sync` отдельным compose-проектом в `~/tabata` на сервере Романа (`157.173.102.230`), подключён к сети `rehabcrm_default`. CRM не трогается, кроме одного блока в её `Caddyfile`.
- Адрес: `https://api.rehab-wellness.app/tabata/` — `handle_path /tabata/*` в блоке `api.` Caddy CRM. Новой DNS-записи не нужно. Слово rehab в адресе Роман разрешил [Роман 26.10].
- Данные: `~/tabata-data/` — git-репозиторий: `workouts.json` (отсортированный, с отступами — читаемые диффы) и `images/<sha>.<ext>`. Каждое изменение — коммит. История = `git log`.
- Доступ: один ключ (32 случайных байта) в `~/tabata/.env`; клиент шлёт `Authorization: Bearer <ключ>`. Ключ вводится один раз на устройство или приходит ссылкой `…/tabata/#key=<ключ>` (приложение сохраняет и убирает его из адресной строки).
- CORS: `https://t0varisch.github.io`, `http://localhost:5173`.
- Ограничения: тело `/sync` до 1 МБ, картинка до 3 МБ, SHA-256 содержимого сверяется с именем.

### Выкладка сервера
- Изменение `Caddyfile` идёт через git CRM → её конвейер выкладки. После выкладки Caddy нужно пересоздать (`docker compose up -d --force-recreate caddy`): файл примонтирован одиночным файлом, git подменяет его новым — контейнер видит старый. CRM недоступна несколько секунд. **Перед этим шагом — подтверждение Романа.**
- Перед пушем — `caddy validate` нового `Caddyfile` в контейнере `caddy:2` на сервере.

## Проверка
- vitest: развёртка фаз, бегунок с подменённым временем, слияние, форматирование времени.
- pytest: слияние, ключ, коммиты истории, проверка SHA картинок.
- Playwright: 390 и 320 px — создать тренировку, прогнать с короткими интервалами, переходы фаз; работа без сети.
- На телефоне Романа: писки поверх музыки, экран не гаснет, синхронизация телефон ↔ компьютер.
